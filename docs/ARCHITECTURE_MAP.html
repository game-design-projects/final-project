Donjon 系统接线图

左边是谁在调用系统，右边是系统内部接了什么。数据来自源码的真实 preload 与调用点（核对于 2026-11-03 的 main 分支），不是凭文件名猜的。

4圆点数字 = 它接到右侧同号分支（①主菜单 ②Genre Halls ③原 Donjon ④Jev ⑤视图 ⑥音频 ⑦存储核心） 虚线红框 = 明确没接 / 没有调用方

读图发现

默认玩法 Genre Halls 完全不调 Jev它没有任何 jev/* 的 preload，怪物 mind 是“Jev 形状的问题 + 本地答案”（界面写着 Offline stand-in for Jev）。真正用 Jev 的只有 main 标志下的原 Donjon。
Jev 只有一个入口game.gd 的 api() → JevApi.handle。6 条路由里 5 条被游戏使用；/api/enemy-turn 游戏内无调用方，只有 cli 场景直接调 Enemy。
说话和麦克风只接在原 DonjonTts / Voice 由 main.gd 创建并挂到 game 上；Genre Halls 只用 Sfx 与 Ambient。
发布包不带 keytools/build.sh --proxy 只写 apiBase 进 jev_config.json，key 在 Worker 的 secret 里，CI 用 JEV_API 指向它。
